# frontend/prototype — 화면 초안 (정적 프로토타입)

React + TypeScript 구현 전에 화면 구성과 사용자 흐름을 먼저 확정하기 위한 **초안**입니다.
빌드 도구 없이 HTML·CSS·바닐라 JS 파일 3개로 되어 있고, 서버 없이 브라우저 `localStorage`에만 저장합니다.
실제 서비스 코드가 아니며, 정식 프런트엔드 구조가 잡히면 이 폴더는 참고용으로만 남기거나 삭제합니다.

- 미리 보기: https://kjooy0305.github.io/testroom/usw-sync/
- 로컬 실행: `frontend/prototype/index.html`을 브라우저로 열면 됩니다. (별도 설치 없음)

## 화면 구성

| 화면 | 조건 | 내용 |
| --- | --- | --- |
| 소개 | 로그인 전 | 서비스 설명 3단 + 시작하기. 머리에는 이름과 로그인 버튼만 |
| 로그인 | — | 이름·학번 입력 (초안이라 비밀번호 없음) |
| PC 대시보드 | 로그인 후, 가로 900px 이상 | 머리: 세부기능·설정·계정 메뉴. 왼쪽 카드 2개(공통 공강, 회의 일정), 가운데 세부 작업 공간, 오른쪽 카드 2개(할 일, 마감 현황). 카드나 세부기능을 누르면 가운데에 열림 |
| 휴대폰 | 로그인 후, 가로 900px 미만 | 공지 한 칸 + 주요 기능 목록(기능 이름 — 현재 상황). 누르면 그 기능 화면으로 진입 |

## 기능 (README의 주요 기능 2~8번에 대응)

| id | 기능 | 초안에서 되는 것 |
| --- | --- | --- |
| `team` | 팀 생성 · 초대 | 팀 이름 수정, 초대 링크 복사(`#/join/코드`), 팀원 추가·내보내기, 역할 수정 |
| `tt` | 시간표 · 가능 시간 등록 | 평일 9~18시 1시간 칸을 눌러 수업(불가) 표시 |
| `free` | 공통 공강 탐색 | 칸마다 가능 인원 계산, 전원 가능 칸 강조, 칸을 눌러 회의 후보로 올리기 |
| `vote` | 회의 시간 추천 · 투표 | 후보 투표, 득표 막대, 전원 가능 시간 추천, 확정 |
| `meet` | 회의 일정 확정 · 관리 | 확정 회의 목록, 직접 추가, 삭제 |
| `task` | 역할 분담 · 할 일 | 담당자·마감이 있는 할 일 체크/추가/삭제 |
| `due` | 마감일 · 진행 상황 | 전체 진행률, 마감 D-day, 팀원별 진행 막대 |

## 구조

```text
frontend/prototype/
├── index.html   # 뼈대 (#root 하나)
├── app.css      # 흑백 스타일. 900px 기준 PC/휴대폰 분기
├── app.js       # 상태(localStorage 'uswsync.v1') · 해시 라우팅 · 화면 렌더
└── README.md
```

- 라우트: `#/` 소개 → `#/login` → `#/app` (대시보드/목록) → `#/app/<기능 id>`
- 설정 메뉴의 "데이터 초기화"로 예시 데이터로 되돌릴 수 있습니다.
- 디자인은 흑백만 사용했습니다. 색·로고·서비스 이름은 미정이라 넣지 않았습니다.

## 정식 구현으로 옮길 때 참고

- 화면 단위는 위 기능 id 7개 + 소개/로그인으로 나누면 됩니다. 각 기능은 `app.js`의 `view<Id>()` 함수 하나가 한 화면입니다.
- 공통 공강 계산(`freeCount`, `allFreeSlots`)과 회의 확정 흐름(후보 → 투표 → 확정 → 회의 일정)은 백엔드 API 설계 시 그대로 옮길 수 있는 규칙입니다.
- 시간표 입력 방식, 공강 계산 기준(1시간 단위·평일만), 투표 정책은 README대로 아직 미확정이며 초안의 값은 예시입니다.
